# Key event handling reports

An Unbroken keyboard protocol extension that lets an application take over specific terminal
keybindings — for example `Cmd+C`/`Cmd+V` on macOS — while keeping the terminal's behavior for
applications that do not care.

## Opt in

The application enables reports with Kitty keyboard progressive-enhancement flag `128` (`1 << 7`).
The highest bit in the current `u8` flag field is used so flags `32` and `64` remain available for
nearer-term upstream additions:

| Sequence       | Meaning                                      |
| -------------- | -------------------------------------------- |
| `CSI > 128 u`  | Push flag 128 and enable universal reports   |
| `CSI < 1 u`    | Pop one keyboard mode and restore its parent |
| `CSI ? u`      | Query the active Kitty keyboard flags        |

The query reply is `CSI ? flags u`; flag 128 is present while the extension is active. Applications
can test support by pushing flag 128 and checking whether the terminal retains it in the query
reply. Keyboard modes have independent stacks for the main and alternate screens and are reset by
a full terminal reset (`RIS`).

While the mode is set, every physical key event forwarded to the application uses the universal
CSI-u representation below. Keys consumed by a non-deferred terminal binding are not forwarded.
The mode does not change bytes produced by binding actions such as `chars`; those are synthetic
binding output rather than physical key events.

## Key events

The wire format is the kitty CSI-u event with an optional fourth report-id parameter:

```
CSI key-code[:shifted[:base]] ; modifiers[:event-type] ; text-codepoints [; report-id] u
```

The modifiers, event type, alternate keys, and associated text have their kitty meanings. Text is
included whenever the physical event produces it. An absent report id means no terminal fallback
is pending and requires no reply. A present report id is always nonzero and identifies the deferred
terminal actions waiting for a handled/unhandled report.

For example:

```
a                    CSI 97;1;97u
Alt+PageUp           CSI 62726;3u
Cmd+Left (id 42)     CSI 62722;9;;42u
Cmd+C (id 43)        CSI 99;9;;43u
```

CSI-u kitty key codes are retained where kitty defines them. Legacy-only functional keys use the
following extension-owned block in Unicode's BMP Private Use Area:

| Key       | Code                     |
| --------- | ------------------------ |
| Insert    | `62720` (`U+F500`)       |
| Delete    | `62721` (`U+F501`)       |
| Left      | `62722` (`U+F502`)       |
| Right     | `62723` (`U+F503`)       |
| Up        | `62724` (`U+F504`)       |
| Down      | `62725` (`U+F505`)       |
| Page Up   | `62726` (`U+F506`)       |
| Page Down | `62727` (`U+F507`)       |
| Home      | `62728` (`U+F508`)       |
| End       | `62729` (`U+F509`)       |
| F1–F12    | `62730`–`62741` (`U+F50A`–`U+F515`) |

The block is scoped to flag 128 and kept well above kitty's currently assigned functional-key
codes. These codes describe the ordinary keys; keypad navigation keeps kitty's distinct `KP_*`
codes. An event without a known key code uses `0`; any associated text still appears in the third
field.

## Reports

After dispatching a key with a nonzero report id, the application answers:

```
CSI ? id ; handled u
```

`handled` is `1` when the application consumed the key and `0` when it did not. On `0`, the
terminal runs the deferred binding actions once. Binding-generated bytes are written directly and
are not recursively reported. On `1`, it does nothing. If no report arrives within 250 ms, the
terminal treats the key as unhandled so a hung or killed application does not lose the user's
terminal shortcuts.

Input ordering is preserved per tab. Once a deferred key has been forwarded, later terminal input
for that tab is held until the report or timeout. An unhandled fallback runs before that queued
input, and only then is input forwarded through the next deferred key. A queued deferred key's
timeout starts when its event is actually sent, not while it is waiting behind an earlier key.

Applications should serialize each handling report with their other terminal output. Transport
fragmentation is safe, but concurrent writers must not insert bytes in the middle of any terminal
escape sequence.

The parameterless form `CSI ? u` remains the kitty keyboard mode query; the private marker and
parameters distinguish handling reports.

## Alacritty configuration

```toml
[keyboard]
bindings = [
    { key = "C", mods = "Command", action = "Copy",  defer = true },
    { key = "X", mods = "Command", action = "Copy",  defer = true },
    { key = "V", mods = "Command", action = "Paste", defer = true },
]
```

`defer` is only valid on key bindings. Before the application enables flag 128, a deferred
binding behaves exactly like a normal terminal binding. With tabs, replies resolve against the tab
that received the key; a deferred action whose tab is no longer active when the reply or timeout
arrives is dropped rather than executed against the wrong terminal.

## Design notes

Universal encoding is tied to the application-controlled mode rather than individual terminal
bindings. This gives the application one input grammar regardless of the user's Alacritty config;
only deferred events append a report id when a terminal fallback is pending.

Terminal keybindings cannot synchronously ask the application about every key — an application on
the other end of an SSH connection would add its round-trip time to every keystroke. Only input
following a deferred key waits for an answer, and that wait is bounded.
